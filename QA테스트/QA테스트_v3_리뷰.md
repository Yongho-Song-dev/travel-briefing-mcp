# Travel Briefing MCP QA 테스트 v3 리뷰 — 경비·식사·일정 현실성 개선

> 문서 작성일: 2026-07-21 (KST)  
> 검토 대상: v1.0.9 `recommend_itinerary` 및 카카오 LLM 최종 응답  
> 테스트 질문: 도쿄 2박 3일 커플 여행, 8월 타이베이 4박 5일 커플 여행  
> 참고 데이터: `curation/`의 국가·도시별 관광지와 `data/`의 국가·도시·여행 목적 정적 매핑

## 1. 종합 결론

현재 응답은 여행지, 기간, 목적에 맞는 기본 골격은 제공하지만 사용자가 실제 여행에 바로 활용하기에는 경비·식사·일정 밀도와 동선이 부족하다. 특히 카카오 LLM이 MCP 원문을 짧게 재작성하면서 `1인`, `항공·숙박 제외` 같은 예산 전제와 식사 메뉴를 삭제해 낮은 금액이 여행 전체 경비처럼 보이는 문제가 크다.

개선의 핵심은 다음 네 가지다.

1. 현지 체류비와 여행 전체 경비를 혼동하지 않도록 인원과 제외 항목을 모든 합계에 표시한다.
2. `현지 로컬 맛집` 대신 도시 대표 음식을 끼니별로 다르게 추천하고 가격대를 함께 제시한다.
3. `자유 시간` 반복을 줄이고 큐레이션 관광지를 실제 이동 권역과 체류시간에 맞게 배치한다.
4. 월을 지정한 질문에는 해당 시기의 장단점, 일정 운영법, 악천후 대안을 명확히 답한다.

## 2. 발견된 문제

### P0-1 — 예산의 기준과 범위가 최종 답변에서 유실됨

- 도쿄 1일 8,700 JPY, 타이베이 1일 1,000 TWD는 카페·간식, 전망대·체험, 예비비 등을 충분히 반영하지 못했다.
- Tool Response의 `1인 · 항공·숙박 제외` 조건이 카카오 답변에서 삭제됐다.
- 커플 여행인데 1인 금액만 노출되고 2인 합계가 없다.
- 절약형과 일반형을 구분하지 않아 지나치게 낮은 단일 값이 표준 경비처럼 보인다.
- 체류 일수를 단순 곱한 합계가 무엇을 포함하는지 명확하지 않다.

### P0-2 — 식사 추천이 플레이스홀더 수준임

- `현지 로컬 맛집`은 음식이나 지역을 추천하지 않는 미완성 문구다.
- 타이베이는 매 끼니마다 `우육면·샤오롱바오·버블티`를 동일하게 반복한다.
- 카카오 최종 답변에서는 점심과 저녁 정보가 대부분 사라졌다.
- 방문 지역, 대표 메뉴, 1인 가격대, 야시장 이용 팁이 연결되지 않는다.

### P0-3 — 4박 5일 일정 중 절반 이상이 비어 있음

- 타이베이 일정은 Day 3 오후부터 Day 5까지 `자유 시간`이 반복된다.
- `카페·산책·쇼핑`만으로는 장소, 소요시간, 동선을 판단할 수 없다.
- 체류 기간에 비해 타이베이 큐레이션 장소 수와 메타데이터가 부족했다.

### P1-1 — 이동 동선과 시간 제약이 부족함

- `시먼딩 → 지우펀 → 국립고궁박물원`은 하루 동선으로 비효율적이고 촉박하다.
- 지우펀을 1시간 30분만 배정한 것은 왕복 교통과 식사를 반영하지 못한다.
- 구역이 없는 관광지는 같은 지역끼리 묶을 수 없어 일정이 단순 우선순위대로 배치된다.
- 장소 간 이동이 `다른 구역`이라고만 표시돼 사용자가 시간 감각을 얻기 어렵다.

### P1-2 — 계절 질문에 대한 판단이 없음

`8월에 타이베이로 가려는데 어때?`는 일정 요청과 함께 여행 적합성 판단을 요구한다. 기존 응답은 태풍 주의 한 문장만 남기고 폭염·습도, 야외 활동 시간 조정, 실내 대안과 항공 변경 가능성을 설명하지 않았다.

### P1-3 — 장소와 맞지 않는 공통 추천 사유

모든 `culture` 장소에 `전통 풍경 배경` 문구를 적용해 현대 건축물인 타이베이 101까지 전통 명소로 설명했다. 장소별 데이터가 없을 때 사용하는 공통 문구는 특정 시대나 풍경을 단정하지 않아야 한다.

### P1-4 — 카카오 LLM의 과도한 요약

카카오 최종 답변에서 다음 핵심 정보가 삭제됐다.

- 1인 기준과 항공·숙박·쇼핑 제외 조건
- 점심·저녁의 대표 음식
- 지도 링크, 장소 설명, 체류시간과 이동 힌트
- 출발일 미정 전제와 시즌 운영법
- 실제 후기와 참고용 데이터라는 주의사항

## 3. 구현 개선 내용

### 3.1 경비

- 도쿄와 타이베이 일반형 정적 경비를 현실화했다.
- 식비 3끼 외에 카페·간식, 일정상 입장료·체험, 예비비를 분리했다.
- 절약형·일반형·여유형의 1인 하루 금액을 함께 표시한다.
- `1인 하루`, `N인 하루`, `전체 일정 N인 현지 체류비`를 각각 표시한다.
- 커플 여행인데 인원 입력이 없으면 2명으로 계산했다는 가정을 명시한다.
- 제목과 합계에 `항공·숙박·쇼핑 제외`를 반복해 축약 시에도 조건이 남게 했다.

### 3.2 식사

- 도쿄와 타이베이 대표 음식 목록을 끼니 수에 맞게 확장했다.
- 한 끼마다 메뉴 하나를 순환 배정해 같은 음식 목록의 반복을 제거했다.
- 직전 관광지의 권역에서 먹도록 지역명을 연결했다.
- 개별 음식점의 폐업·영업시간 위험을 피하기 위해 검증되지 않은 가게명은 만들지 않는다.
- 각 메뉴에 정적 식비를 기반으로 한 1인 참고 가격 범위를 표시한다.

### 3.3 일정과 동선

- 타이베이에 중정기념당, 화산1914, 디화제·다다오청, 베이터우, 단수이, 샹산, 송산문창원구, 닝샤 야시장을 추가했다.
- 추가 장소의 운영·관광 정보는 [타이베이시 공식 관광 사이트](https://www.travel.taipei/zh-tw/attraction/all-regions?location=141&page=1&sortby=Location)와 [신베이시 공식 단수이 관광 정보](https://newtaipei.travel/zh-tw/tour/986)를 기준으로 재확인했다.
- 타이베이 기존 장소에도 권역 정보를 추가했다.
- 지우펀은 최소 6시간의 근교 일정으로 표시해 도심 명소와 같은 오후에 섞이지 않게 했다.
- 같은 권역은 도보 약 10분, 다른 권역은 대중교통 약 30분의 추정 이동시간을 표시한다.
- 관광지가 소진될 경우에도 동일한 `자유 시간` 문구 대신 현재 권역의 휴식·상권 산책 계획과 소요시간을 제공한다.

### 3.4 계절과 응답 보존

- `data/TW.json`에 7~9월 월별 여행 판단, 일정 운영법, 날씨 대안을 추가했다.
- 출발 월이나 정확한 날짜가 입력된 경우에만 월별 판단을 노출한다.
- 커플 문화 명소의 공통 설명을 시대에 중립적인 문구로 변경했다.
- Tool description의 앞부분에 출력 계약을 두고, 최종 답변이 상단 `먼저 보는 핵심 요약`부터 시작하도록 명시했다.
- 상세 일정에서 여행 판단·커플 2인 예산·제외 조건·Day별 관광지와 음식을 추출해 응답 최상단에 다시 배치했다.
- 예산은 `커플 2인 · 일반형 4,800 TWD/일 · 5일 24,000 TWD · 항공·숙박·쇼핑 제외`처럼 전제를 한 문장에 결합했다.
- 후기 본문은 일정이 있는 응답에서 2건의 제목·작성자·날짜·링크만 한 줄로 남겨 핵심 일정이 뒤로 밀리지 않게 했다.

## 4. 완료 기준

- `현지 로컬 맛집`만 단독으로 출력하지 않는다.
- 동일한 대표 음식 목록을 매 끼니 반복하지 않는다.
- 음식 슬롯에 도시 대표 메뉴와 1인 가격대가 포함된다.
- 커플 여행 경비에 2인 하루 및 전체 일정 금액이 표시된다.
- 모든 경비 합계에서 항공·숙박·쇼핑 제외 여부를 오해하지 않게 한다.
- 4박 5일 타이베이 일정의 중간 날짜가 `자유 시간`으로만 채워지지 않는다.
- 지우펀과 고궁박물원을 촉박한 동일 오후 일정으로 배치하지 않는다.
- 8월 타이베이 질문에 여행 가능 여부, 더위·태풍 대응, 실내 대안이 포함된다.
- 장소 간 권역과 추정 이동시간이 표시된다.
- 응답 첫 블록만 사용해도 월별 판단, 2인 예산과 제외 조건, 모든 Day의 장소·음식이 함께 남는다.
- 카카오 LLM이 상단 핵심 요약과 MCP 원문의 지도·경고를 유지하도록 도구 설명이 안내한다.

## 5. 추가 권고

호스트 LLM의 출력 길이 제한이나 시스템 프롬프트가 MCP 결과를 강제로 축약한다면 서버 수정만으로 모든 정보 손실을 막을 수 없다. 카카오 측 최종 응답 프롬프트에도 `일자별 식사`, `예산 인원·제외 항목`, `월별 주의사항`을 필수 보존 필드로 지정하고, 원문의 지도 URL과 경고 문구를 삭제하지 않는 회귀 테스트를 별도로 운영해야 한다.

## 6. 카카오 LLM 특성 기준 재검토

제공된 두 결과를 비교하면 카카오 LLM은 Tool Response를 그대로 전달하기보다 약 600~800자 안팎의 일정 골격으로 강하게 재구성하는 경향이 있다. 제목, Day 번호, 대표 관광지, 가장 단순한 합계는 비교적 잘 남지만 다음과 같은 하위 정보는 우선 삭제됐다.

- 장소 설명 아래에 분리된 지도 링크·체류시간·이동 힌트
- 독립된 점심·저녁 줄과 구체적인 메뉴
- 비용 섹션의 `1인`, 포함·제외 조건 및 산정 근거
- 후기 출처와 출발일 미정 전제
- 계절 정보 중 일정 운영법과 대체 일정

따라서 “상세 내용을 모두 보존하라”는 도구 설명만으로는 의도한 결과를 안정적으로 만들기 어렵다. 중요한 필드가 서로 다른 줄과 섹션에 흩어져 있으면 카카오가 일부만 선택하면서 의미가 달라질 수 있으므로, 삭제되면 안 되는 값은 짧고 독립적으로 완결된 문장에 함께 있어야 한다.

### 6.1 반영한 권장 구조

1. 헤더와 여행 조건 직후에 `먼저 보는 핵심 요약`을 배치한다.
2. 월별 질문이면 여행 가능 여부를 요약의 첫 항목으로 넣는다.
3. 예산은 인원, 1일 금액, 전체 기간 금액, 제외 항목을 하나의 원자적 문장으로 묶는다.
4. 각 Day는 관광지와 식사를 같은 줄에 결합하고, 음식 가격대까지 함께 둔다.
5. 상세 코스·준비사항·지도 링크는 아래에서 그대로 제공하되 후기 스니펫은 한 줄 메타로 압축한다.
6. Tool description의 앞부분에 `OUTPUT CONTRACT`를 두어 카카오가 핵심 요약부터 복사하도록 한다.

실제 렌더링 기준으로 도쿄 핵심 요약은 약 440자 이내, 8월 타이베이 핵심 요약은 약 640자 이내에 여행 판단·예산·전체 Day·식사가 포함된다. 카카오가 기존과 비슷한 길이로 축약해도 이전보다 핵심 조건이 남을 가능성이 높다.

### 6.2 예상 결과와 한계

- 일정의 Day 구조, 커플 2인 예산, 항공·숙박·쇼핑 제외 조건, 대표 음식은 이전보다 높은 확률로 유지될 것으로 판단한다.
- 지도 URL, 이동시간, 상세 준비사항은 핵심 요약 아래에 있으므로 카카오의 최종 길이가 매우 짧으면 여전히 생략될 수 있다.
- MCP 서버는 호스트 LLM의 실제 토큰 제한과 시스템 프롬프트를 통제할 수 없다. 따라서 배포 후 동일한 도쿄·타이베이 질문을 카카오에서 다시 실행해 최종 답변을 비교하는 종단 회귀 테스트가 필요하다.
